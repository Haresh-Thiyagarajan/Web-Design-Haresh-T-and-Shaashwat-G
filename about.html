Planning, Development, and Implementation

Planning

  • Read the assignment closely. The 2026–2027 topic asks for “organizations, programs, services, events, and resources.” We gave each one its own page, using those exact words in the menu, so nothing is hidden.
  • Picked a real community. We chose our own city, Sammamish, Washington. Real places let us use real, citable sources instead of made-up content.
  • Studied what residents already know. We modeled the layout on the official City of Sammamish website: a top bar, a main menu, a large banner with the city name, a row of category links, and a footer with City Hall information. Residents already know where to look, so they need less time to learn the site.
  • Researched every listing. We gathered facts from official sources (City of Sammamish, King County Library System, Washington 211) and recorded the date we checked each one.

Development

  • Plain HTML, CSS, and JavaScript. There is no framework and no build step, so the site loads quickly and is easy to maintain.
  • Works without internet. Fonts, icons, and photos are stored with the website itself, so it still works if the connection drops. That matters for residents with limited data, and for our presentation.
  • One data file. Every listing lives in one file (js/data.js). Each page reads from it, so a correction made once shows up everywhere, including in search and on the Sources page.
  • One shared header and footer. One script builds the same header, menu, and footer on every page, so the pages can’t drift apart.

Implementation

  • Version control. The code is stored on GitHub, so both team members can work on it and every change is tracked.
  • Hosting. The site is published free with GitHub Pages, which uses a secure HTTPS connection.
  • Testing checklist. Before each update we check the site on a desktop browser, a tablet, and a phone. We also try every interactive feature using only the keyboard, and run Google Lighthouse for accessibility and performance.

Website UX Design

Colors

Our green palette comes from Sammamish itself: its evergreen forests and the blue of Lake Sammamish. Every text color passes the WCAG 2.2 AA contrast minimum of 4.5:1.

  • Evergreen#1E6B45 · menu and buttons
    6.5:1 with white
  • Forest#0F2A1D · top bar and footer
    14.6:1 page text
  • Gold#F2C14E · highlights on dark
    9.1:1 on forest
  • Mist#F1F7F3 · page headers
    background tint
  • Lake blue#1B5E8C · saved and next-date
    6.9:1 with white

Fonts

  • Atkinson Hyperlegible for body text. The Braille Institute designed it for readers with low vision: letters that are easy to confuse, like I, l, and 1, have distinct shapes.
  • Bricolage Grotesque for headings. It is friendly and bold, and it makes headings easy to scan.

Graphics

We use real photos of Sammamish places and one consistent set of line icons, one icon for each category. There are no AI images. Photo credits are listed on the Sources page.

Accessibility Features

  • Text size buttons (A− and A+) and a High contrast mode in the top bar on every page. Your choice is remembered.
  • A “Skip to main content” link, clear headings, and labeled regions for screen readers.
  • Everything works with a keyboard, with a thick, high-contrast focus outline, and every button responds visibly when pressed.
  • Every photo has descriptive alternative text.
  • Animations turn off automatically for visitors who set “reduce motion” on their device, and the see-through menu bar turns solid for “reduce transparency”.
  • The site follows each visitor’s light or dark setting automatically, with every color checked for contrast in both.
  • Crisis numbers (988 and 2-1-1) appear at the top of every page.

Website Evaluation

Website is compatible with multiple platforms

The layout is responsive. It rearranges itself for each screen size instead of shrinking.

  • Desktop (1280px and wider): the full menu, a five-across category row, and listings with the photo, description, and details side by side.
  • Tablet (about 768–1080px): three-across categories, and listings with the photo beside the text.
  • Phone (about 390px): a Menu button opens the navigation, listings stack in one column, and every button and filter is at least 44px tall for easy tapping (the size Apple recommends).
  • Browsers: built with standard HTML, CSS, and JavaScript supported by current Chrome, Safari, Edge, and Firefox.

Website interactivity functions and is error free

  • Site-wide search: the search box in the header searches all five categories as you type. It also understands everyday words, so “groceries” finds food help and “lawyer” finds legal aid.
  • Topic filters: each category page has filter buttons and its own search box, with a live count of results.
  • Automatic event dates: the Events page works out the next date for repeating events (like “1st and 3rd Tuesdays”), and can filter to the next 7 or 30 days.
  • My List: save any listing, see your list from any page, and print it as a one-page resource sheet.
  • Accessibility controls: text size and high contrast, remembered between visits.
  • Mobile menu: opens and closes with one tap.

Website elements are consistent across all pages

  • The same top bar, header, search, menu, and footer on every page, built by one shared script.
  • The menu always lists the pages in the same order, and highlights the page you are on.
  • Every category page uses the same layout: breadcrumb, page title with icon, search, topic filters, then listings.
  • Every listing has the same parts in the same order: name, type, topics, description, source, details, and a Save button.
  • One stylesheet controls all colors, fonts, and spacing.

Description of metrics planned to use to measure the success of the website

These are the measurements we plan to use once the website has visitors. We have not collected results yet.

MetricWhat it tells us, and our goal
Task success rateIn usability tests, the share of testers who find a requested resource (for example, “find food help”). Goal: 90% or more.
Time on taskHow long it takes a tester to find a resource. Goal: under 30 seconds.
System Usability Scale (SUS)A standard 10-question usability survey. Goal: a score of 80 or higher.
Search zero-result rateHow often a search finds nothing. This tells us which words to add. Goal: under 5%.
Bounce rate and engagement timeMeasured with Google Analytics 4. Shows whether visitors leave right away or explore.
Conversion eventsHow often visitors use Save to My List, print, or tap a phone number. These are the real signs that someone found help.
Core Web VitalsGoogle’s speed measures. Goals: Largest Contentful Paint (LCP) under 2.5 s, Interaction to Next Paint (INP) under 200 ms, and Cumulative Layout Shift (CLS) under 0.1.
Lighthouse scoresAutomated audit. Goals: Accessibility 100, Performance 90 or higher.
Content freshnessThe share of listings checked within the last 90 days. Goal: 100%.

Website Content: Grammar, spelling, and punctuation

We wrote every page in plain, friendly language. Both team members proofread every page, and we checked all text with a spell checker before publishing. Organization names are spelled the way the organizations spell them.
